# 0.2.0 — migration produit (candidate non publiée)

La qualification et la publication ne sont pas acquises par cette note. Version
courante : `0.2.0-dev`. Le rapport P7.2 et ses logs indiquent les gates observées,
les échecs conservés et les correctifs autorisés ; P8 n'est pas exécutée ici.

## Architecture

Neuf crates sous `rust/` séparent contrats, contexte pur, flows/packages, compiler
pur, runtime ADK, stockage, service d'exécution, HTTP et CLI. `zf-execution` porte
le cycle de vie indépendamment de HTTP. ADK-Rust 2.2.0 reste le moteur ; son
catalogue complet et les pins externes sont conservés.

`@zedflow/sdk` expose les contrats Zod et transports à partir de son artefact
construit. `@zedflow/vue` possède le lifecycle Vue. Le client et Electron vivent
sous `web/apps`, les tests navigateur dans le projet indépendant `e2e/`.

## Identités et conservation

Les nouveaux flows utilisent `.zedflow/flow/<id>/flow.json` et `flow.rs`, avec
inventaire et dépendances locales figées. Les quatre racines de fichiers legacy
restent lisibles ; conversion/import sont explicites. Une révision de package
couvre assets et dépendances, distinctement du hash exact du Rust exécuté. Les
pins d'admission et de définition ne remplacent pas les hashes des sources
historiques. Les exports Cargo transportent les sources exactes et leur lock.

La migration des tests conserve les assertions de reprise, reçus d'effets,
contexte profondeur64/65, contrôles de workspace et publication atomique. Le
ledger distingue déplacements produit et retrait des expériences lab. Les preuves
de qualification associent les résultats aux empreintes des sources exécutées.

## Écarts et limites

- L’import de la table SQLite historique `compositions` est une commande offline
  explicite, avec sauvegarde cohérente et reçu reprenable. La table et les sessions
  restent conservées. Un import incomplet bloque l’admission ; les collisions
  n’écrasent pas les fichiers. Voir le parcours d’import des packages.
- Les corrections du routage et des lectures du catalogue passent leurs tests
  ciblés et la suite Rust complète, avec les délais et assertions d’origine.
  Le cache des sources conserve la validation sémantique à chaque lecture ;
  les captures de fichiers restent fraîches.
- Les tests navigateur attendent les réponses serveur et l’initialisation de
  la caméra avant de comparer les états. Les rapports de qualification conservent
  les échecs observés, leurs reproductions et les résultats après correction.
- Les résultats des anciennes suites lab ne qualifient pas ce diff. Toute gate
  échouée ou non relancée après correctif reste une limite de la candidate.
- Les fixtures ne prouvent ni qualité LLM ni accès cloud. Aucun appel modèle réel,
  poids, activation personnelle ou publication n'a été réalisé dans P7.2.
- CI cible Ubuntu ; un smoke Linux local ne qualifie pas macOS/Windows. Pas
  d'installateur universel ni de registre distant annoncé.
- Les manifests de support exportés conservent leurs dev-dependencies, comme
  auparavant : tout nouvel edge doit rester cohérent avec le lock d'export.

Les commandes actuelles sont dans [validation](../validation.md), le parcours
source dans [packages de flows](../development/flow-packages.md), et l'exemple
complet sous `examples/working-system`. Les opérations de publication/maintenance
personnelle suivent les étapes P8 du plan de migration approuvé, après qualification.

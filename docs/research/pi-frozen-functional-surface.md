# Research: Inventaire de la surface fonctionnelle normative du Pi figé

## Summary
La surface normative de Stage 1 est celle de `references/pi@2b00dade7cec918aefb025c8b7a4fa304a30acdd`, non celle de Pi actuel. Elle comprend quatre paquets stables et publiés (AI, Agent, TUI, coding-agent), plus l’orchestrateur explicitement expérimental; le CLI assemble les trois premiers et expose les modes interactif, print, JSON, RPC et SDK. Les docs figées sont la source principale; les exports et manifests figés complètent les surfaces publiques ou testables que les docs n’énumèrent pas.

## Findings
1. **Périmètre, dépendances et statut** — Le README racine définit les quatre produits publiés: API LLM unifiée (`pi-ai`), runtime agent (`pi-agent-core`), CLI coding-agent et bibliothèque TUI; le manifeste racine construit aussi `orchestrator`. Les manifests confirment les dépendances en couches `coding-agent → agent, ai, tui`, `agent → ai`, et l’orchestrateur → coding-agent. Le README d’orchestrator le marque toutefois *experimental*, instable et susceptible d’être supprimé: son existence doit être portée, mais il ne faut pas lui attribuer la stabilité normative des quatre autres. [README racine figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/README.md) · [manifest racine](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/package.json) · [orchestrator README](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/orchestrator/README.md)

2. **`pi-ai`: contrat de transport LLM multi-provider** — Le paquet fournit catalogues de modèles/provider, résolution d’authentification (clé/OAuth/credential store), `Models.stream`/`complete`, messages et contenus texte/image/thinking/tool-call, validation TypeBox, coûts/tokens, erreurs/abort/retry, sérialisation et handoff de contexte, image generation, providers personnalisés et faux provider de tests. Le flux de stream est normatif (`start`, deltas texte/thinking/tool-call, `done`/`error`), de même que les résultats d’outil rattachés par `toolCallId`. La liste de providers est extensible mais les transports documentés incluent au minimum les implémentations Anthropic, OpenAI (completions/responses/Codex), Google/Vertex, Bedrock, Mistral et les compatibilités OpenAI. [AI README figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/ai/README.md) · [exports AI figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/ai/src/index.ts) · [manifest AI](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/ai/package.json)

3. **`pi-agent-core`: boucle stateful et sémantique d’événements/outils** — `Agent` maintient system prompt, modèle, thinking level, outils, messages, état de streaming et erreurs; il transforme le contexte puis le convertit en messages LLM. `prompt()` et `continue()` émettent les événements agent/turn/message/tool dans l’ordre documenté. La concurrence d’outils est particulièrement normative: préflight séquentiel, exécution parallèle par défaut, événements de fin dans l’ordre de complétion, mais messages persistés et `turn_end.toolResults` dans l’ordre source; un outil `sequential` rend le lot entier séquentiel. `beforeToolCall`, `afterToolCall`, `terminate`, annulation et arrêt après tour sont donc des comportements à conserver. Le code exporte en outre la harness: compaction, résumé de branche, persistence JSONL et mémoire, skills, templates, system prompt, proxy et utilitaires de troncature — surfaces non résumées par le README mais publiques dans l’index. [Agent README figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/agent/README.md) · [exports Agent figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/agent/src/index.ts) · [manifest Agent](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/agent/package.json)

4. **`pi-tui`: rendering terminal et composants** — Le contrat est un rendu différentiel synchronisé (CSI 2026), composants `render(width) -> string[]`, entrée brute optionnelle et invalidation; toute ligne doit respecter la largeur. La TUI gère focus, overlays avec ordre de résolution/retour de focus, raw terminal, paste bracketed, key parsing (dont Kitty), autocomplete, IME via `CURSOR_MARKER`, thèmes et images Kitty/iTerm2. La frontière exportée est plus large que la liste de composants documentée: terminal `ProcessTerminal`, `StdinBuffer`, keybindings, fuzzy matching, largeur ANSI/wrapping, couleurs, détection/caches de capacités et encodage d’images sont tous exports publics. [TUI README figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/tui/README.md) · [exports TUI figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/tui/src/index.ts) · [manifest TUI](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/tui/package.json)

5. **`pi-coding-agent`: modes et CLI normatifs** — Le CLI fournit les modes interactif, `-p/--print`, `--mode json`, `--mode rpc` et l’SDK `AgentSession`; ses outils built-in sont `read`, `bash`, `edit`, `write`, `grep`, `find`, `ls`, avec allowlist/exclusion/désactivation. L’interactif couvre sélection provider/modèle, thinking, files `@`, complétion, images, commandes shell `!`/`!!`, queues steering/follow-up, commandes slash, sessions/branches/fork/clone/export/import/share, compaction et trust de projet. Les options de contexte/ressources et la priorité explicite des flags sont à conserver. [README coding-agent figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/README.md) · [guide usage figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/docs/usage.md) · [manifest coding-agent](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/package.json)

6. **Persistance et intégration machine** — Les sessions sont JSONL version 3, organisées comme arbre par `id`/`parentId`; loader migre v1/v2 vers v3. Il faut conserver header, rôles de message de base et rôles étendus (`bashExecution`, `custom`, `branchSummary`, `compactionSummary`), ainsi que les entrées model/thinking/compaction/branch/custom/custom_message/label. JSON mode émet d’abord le header puis les événements de session, queue, compaction et retry; RPC est JSONL strict délimité uniquement par LF (accepte CRLF après retrait de CR), avec réponse corrélable par `id` et événements asynchrones. Cette règle exclut délibérément les lecteurs qui scindent U+2028/U+2029. [format de session figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/docs/session-format.md) · [mode JSON figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/docs/json.md) · [mode RPC figé](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/docs/rpc.md)

7. **Extensions, ressources, trust et packages sont une surface centrale, non optionnelle** — Les extensions TS (chargées par jiti) peuvent s’abonner au cycle de vie, intercepter les appels/payloads provider, modifier contexte/compaction, enregistrer tools/commands/shortcuts/flags/providers/renderers, piloter l’UI et persister des entrées. Elles s’exécutent avec les permissions intégrales de l’utilisateur; les ressources projet ne chargent qu’après trust, tandis que globales/CLI restent disponibles avant la décision. Skills, prompt templates et thèmes sont des ressources chargeables globalement/projet/CLI. Les Pi Packages installables npm/git/URL/local déclarent ou découvrent extensions, skills, prompts et thèmes; sources git sont épinglées et les packages se dédoublonnent selon leur identité. [extensions figées](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/docs/extensions.md) · [packages figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/docs/packages.md) · [exports SDK/extensions figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/src/index.ts)

8. **Surfaces source-only de `coding-agent` et orchestrator** — L’index public coding-agent expose, au-delà des docs utilisateur, parseArgs/config, stockage auth (fichier et mémoire), registry/résolution de modèles, settings, resource/package loader, outil factories et opérations, event bus, manager/session parser/migrations, compaction, diff/patch, SDK factories et le vaste contrat de types extension. L’index orchestrator expose config, handler, protocole/client/server IPC, rpc-process, serveur, stockage, supervisor et types; c’est l’inventaire minimal de ce package expérimental. Les scripts `test` montrent les oracles de régression disponibles: Vitest pour AI/Agent/coding-agent et `node --test` pour TUI. [exports coding-agent figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/coding-agent/src/index.ts) · [exports orchestrator figés](https://github.com/earendil-works/pi/blob/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages/orchestrator/src/index.ts) · [manifests figés](https://github.com/earendil-works/pi/tree/2b00dade7cec918aefb025c8b7a4fa304a30acdd/packages)

## Gaps
- Cet inventaire catégorise la surface; il ne remplace pas une matrice symbole-par-symbole des `.d.ts` générés ni un relevé exhaustif de chaque commande RPC/événement extension. Cette matrice doit être dérivée du même SHA seulement si un gate exige une couverture API exhaustive.
- L’orchestrator n’a qu’un README minimal et est explicitement expérimental; ses sémantiques détaillées exigent lecture directe des modules `src/` et de leurs tests, pas inférence depuis le CLI.
